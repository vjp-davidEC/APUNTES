Fundamentos de Concurrencia y Procesos en Java

Resumen teórico exhaustivo correspondiente a la Unidad Temática 1 del módulo PSP. Aprende cómo el SO y la JVM gestionan la ejecución concurrente, los recursos compartidos, la sincronización mediante monitores y la comunicación entre hilos.

1.1 Programas, Procesos e Imagen de Memoria

Un Programa es un conjunto estático de instrucciones almacenado en disco (equivalente al concepto de Clase en POO). Para que haga algo, debe ponerse en ejecución, dando lugar a uno o varios Procesos (entidad dinámica, equivalente a un Objeto).

Estructura de la Imagen de Memoria:

  • Código / Texto: Instrucciones ejecutables del programa.
  • Datos: Constantes y variables estáticas.
  • Pila (Stack): Argumentos de funciones, retornos y variables locales.
  • Heap (Memoria Dinámica): Memoria reservada dinámicamente.
// Vista Simplificada de PCB (Process Control Block)
+---------------------------------------+
| ID del Proceso (PID) |
| Estado del Proceso (Listo, Ejec, etc) |
| Registros de la CPU (Program Counter) |
| Tablas de Páginas de Memoria |
| Archivos abiertos e E/S |
+---------------------------------------+

El SO utiliza las tablas PCB para gestionar el cambio de contexto entre procesos.

1.2 Ciclo de Vida de un Proceso y Planificación

1. Creado
2. Listo (Ready)
3. Ejecución
4. Bloqueado
5. Terminado

El Planificador de Procesos (Scheduler) asigna rodajas de tiempo (cuantum) a los procesos en estado Listo. Si el cuantum se agota o se abandona voluntariamente, regresa a Listo. Si espera una operación de E/S o suceso, pasa a Bloqueado. El cambio entre estados se denomina Cambio de Contexto.

1.3 Concurrencia vs Paralelismo (Ejemplo de los Albañiles)

Secuencial

1 Albañil - Pared a Pared

Construye la pared 1 completa, luego la 2, luego la 3 y finalmente la 4. Sin solapamientos.

Paralelismo

2 Albañiles Simultáneos

Cada albañil construye paredes al mismo instante físico en diferentes CPUs/núcleos. Reduce el tiempo a la mitad.

Concurrencia

1 Albañil Intercalando

Pone 2 ladrillos en la pared 1, 2 en la pared 2, 2 en la 3... Intercala tareas progresando en todas de forma solapada.

1.4 Problemas Clásicos de Concurrencia

Exclusión Mutua

Solo un proceso debe acceder a un recurso compartido (Sección Crítica) a la vez. Ejemplo: Juego del pañuelo o impresora compartida.

Condición de Sincronización

Un proceso debe esperar a que ocurra un evento para continuar. Ejemplo: Un jugador debe esperar a que el juez diga su número.

Interbloqueo (Deadlock)

Todos los procesos esperan por un evento que nunca ocurrirá (Abrazo Mortal). El sistema se congela por completo.

1.5 Procesos vs Hilos (Threads) en Java

Un Hilo es una secuencia de control ligera dentro de un proceso. Mientras que los procesos son entidades pesadas con espacio de memoria aislado en el núcleo, los hilos residen en el espacio de usuario y comparten la memoria del proceso (código y datos), haciendo que los cambios de contexto sean muy eficientes.

Característica Proceso Hilo (Thread)
Peso / Recursos Pesado (Estructura en núcleo / PCB) Ligero (Espacio de usuario)
Memoria Espacio de direcciones aislado Memoria compartida del proceso padre
Cambio de Contexto Costoso en tiempo de CPU Rápido y de bajo consumo

1.6 Monitores y Métodos de Coordinación (`synchronized`, `wait`, `notify`)

Java asigna a cada objeto un monitor implícito (cerrojo / lock). La palabra clave synchronized asegura que solo un hilo a la vez ejecute un bloque o método protegido sobre ese objeto.

wait()

Hace que el hilo libere el cerrojo y se ponga en espera hasta que otro hilo invoque notify() o notifyAll(). Debe estar dentro de un bucle while.

notify()

Despierta al primer hilo que llamó a wait() sobre el mismo objeto monitor.

notifyAll()

Despierta a todos los hilos en espera sobre el monitor. Es la opción recomendada.

Método 2: Creación Implementando la Interfaz Runnable (Recomendado)

¿Por qué es superior? Java no admite herencia múltiple. Si heredas de Thread, la clase no podrá heredar de ninguna otra. Implementando Runnable mantienes libre la herencia. 

package es.iesvjp.psp;

public class ThreadConRunnable implements Runnable {
    private String palabra;

    public ThreadConRunnable(String palabra) {
        this.palabra = palabra;
    }

    @Override
    public void run() {
        for (int i = 0; i < 10; i++) {
            System.out.println(palabra);
        }
    }
}

// Clase Principal
public class MainRunnable {
    public static void main(String[] args) {
        ThreadConRunnable a = new ThreadConRunnable("Hilo 1");
        ThreadConRunnable b = new ThreadConRunnable("Hilo 2");

        // Pasamos el objeto Runnable al constructor de Thread
        Thread th1 = new Thread(a);
        Thread th2 = new Thread(b);

        th1.start();
        th2.start();
        System.out.println("Fin del hilo principal");
    }
}

Caso 1: El Banco (Condición de Carrera y Cerrojos)

Escenario: Ana y Juan comparten una cuenta bancaria con 50€. Ambos intentan retirar dinero al mismo tiempo. Si el método retirar() no es atómico, ambos leen un saldo suficiente de 50€ y retiran dinero simultáneamente, dejando la cuenta en saldo negativo (-10€).

Solución: Marcar el método retirar como synchronized. Al hacerlo, el hilo toma el monitor de la instancia de Cuenta y la otra persona debe esperar a que termine la operación completa. 
// 1. Clase Cuenta Sincronizada
public class Cuenta {
    private double saldo;

    public Cuenta(double saldo) {
        this.saldo = saldo;
    }

    public double getSaldo() {
        return saldo;
    }

    // Al declarar synchronized, evitamos saldos negativos
    public synchronized void retirar(double cantidad, String persona) {
        if (getSaldo() >= cantidad) {
            System.out.println("Se va a retirar dinero. El saldo actual es de: " + getSaldo() + "€");
            saldo = saldo - cantidad;
            System.out.println(persona + " retira " + cantidad + " €. (Saldo actual: " + getSaldo() + "€)");
        } else {
            System.out.println(persona + " no puede retirar " + cantidad + " € porque el saldo actual es insuficiente: " + getSaldo() + "€");
        }
        if (getSaldo() < 0) {
            System.out.println("SALDO NEGATIVO: " + getSaldo());
        }
    }
}

// 2. Clase Persona
public class Persona extends Thread {
    private String nombre;
    private Cuenta cuenta;

    public Persona(String nombre, Cuenta cuenta) {
        this.nombre = nombre;
        this.cuenta = cuenta;
    }

    @Override
    public void run() {
        for (int i = 0; i < 4; i++) {
            this.cuenta.retirar(10, this.nombre);
            try {
                Thread.sleep(1000);
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
        }
    }
}

// 3. Clase Principal
public class PrincipalBanco {
    public static void main(String[] args) {
        Cuenta cuenta = new Cuenta(50);
        Persona ana = new Persona("Ana", cuenta);
        Persona juan = new Persona("Juan", cuenta);

        ana.start();
        juan.start();
    }
}

Caso 2: Modelo Productor - Consumidor (Cola Monitor)

Un hilo Productor genera números en un búfer/cola compartido y un hilo Consumidor los consume. Se requiere sincronización estricta: el productor debe esperar si la cola está llena, y el consumidor si está vacía. 

// 1. Monitor Búfer / Cola
public class Cola {
    private int numero;
    private boolean llena = false; // inicialmente vacía

    public synchronized void put(int valor) {
        while (llena) { // SIEMPRE usar bucle while con wait
            try {
                wait();
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
        }
        this.numero = valor;
        llena = true;
        System.out.println("=> Productor, produce: " + valor);
        notifyAll(); // Notifica a los consumidores en espera
    }

    public synchronized int get() {
        while (!llena) {
            try {
                wait();
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
        }
        llena = false;
        System.out.println("<= Consumidor, consume: " + this.numero);
        notifyAll(); // Notifica al productor en espera
        return this.numero;
    }
}

// 2. Productor
public class Productor extends Thread {
    private Cola cola;

    public Productor(Cola cola) {
        this.cola = cola;
    }

    @Override
    public void run() {
        for (int i = 1; i <= 5; i++) {
            cola.put(i);
            try { sleep(1000); } catch (InterruptedException e) { e.printStackTrace(); }
        }
    }
}

// 3. Consumidor
public class Consumidor extends Thread {
    private Cola cola;

    public Consumidor(Cola cola) {
        this.cola = cola;
    }

    @Override
    public void run() {
        for (int i = 1; i <= 5; i++) {
            int valor = cola.get();
            try { sleep(1000); } catch (InterruptedException e) { e.printStackTrace(); }
        }
    }
}

// 4. Principal
public class PrincipalProdCons {
    public static void main(String[] args) {
        Cola cola = new Cola();
        Productor prod = new Productor(cola);
        Consumidor con = new Consumidor(cola);

        prod.start();
        con.start();
    }
}

Repaso 2. El aparcamiento: aforo máximo de cuatro coches

Ocho coches compiten por cuatro plazas. Los que encuentran el aparcamiento lleno esperan hasta que otro salga.

Código de referencia para este ejercicio. Revisa la solución y adapta los nombres de las clases y de los componentes a lo que pide el enunciado. 

// Aparcamiento.java
public class Aparcamiento {
    private int dentro = 0;
    private final int capacidad = 4;

    public synchronized void entrar(String coche) throws InterruptedException {
        while (dentro >= capacidad) {
            System.out.println(coche + " espera: aparcamiento lleno");
            wait();
        }
        dentro++;
        System.out.println(coche + " entra. Ocupación: " + dentro);
    }

    public synchronized void salir(String coche) {
        dentro--;
        System.out.println(coche + " sale. Ocupación: " + dentro);
        notifyAll();
    }
}

// Coche.java
public class Coche extends Thread {
    private final Aparcamiento parking;

    public Coche(String nombre, Aparcamiento parking) {
        super(nombre);
        this.parking = parking;
    }

    @Override
    public void run() {
        try {
            parking.entrar(getName());
            Thread.sleep(3000);
            parking.salir(getName());
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
    }
}

// PrincipalParking.java
public class PrincipalParking {

Repaso 4. Fábrica: productor y dos consumidores

Almacén con capacidad tres. El productor fabrica diez productos y dos consumidores los retiran hasta que se hayan consumido todos.

SOLUCIONES DEL REPASO

Código de referencia para este ejercicio. Revisa la solución y adapta los nombres de las clases y de los componentes a lo que pide el enunciado. 

// Almacen.java
import java.util.LinkedList;
import java.util.Queue;

public class Almacen {
    private final Queue<Integer> productos = new LinkedList<>();
    private final int capacidad = 3;
    private boolean terminado = false;

    public synchronized void producir(int valor) throws InterruptedException {
        while (productos.size() == capacidad) wait();
        productos.add(valor);
        System.out.println("Produce: " + valor + " | Almacén: " + productos);
        notifyAll();
    }

    public synchronized Integer consumir() throws InterruptedException {
        while (productos.isEmpty() && !terminado) wait();
        if (productos.isEmpty() && terminado) return null;
        int valor = productos.remove();
        System.out.println(Thread.currentThread().getName()
                + " consume: " + valor + " | Almacén: " + productos);
        notifyAll();
        return valor;
    }

    public synchronized void finalizarProduccion() {
        terminado = true;
        notifyAll();
    }
}

// Productor.java
public class Productor extends Thread {
    private final Almacen almacen;

    public Productor(Almacen almacen) { this.almacen = almacen; }

    @Override
    public void run() {
        try {
            for (int i = 1; i <= 10; i++) {
                almacen.producir(i);
                Thread.sleep(300);
            }
            almacen.finalizarProduccion();
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            almacen.finalizarProduccion();
        }
    }
}

// Consumidor.java
public class Consumidor extends Thread {
    private final Almacen almacen;

    public Consumidor(String nombre, Almacen almacen) {
        super(nombre);
        this.almacen = almacen;
    }

    @Override
    public void run() {
        try {
            Integer valor;
            while ((valor = almacen.consumir()) != null) {
                Thread.sleep(500);
            }
            System.out.println(getName() + " termina.");
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
    }
}

// PrincipalFabrica.java
public class PrincipalFabrica {
    public static void main(String[] args) {
        Almacen a = new Almacen();
        Productor p = new Productor(a);
        Consumidor c1 = new Consumidor("Consumidor 1", a);
        Consumidor c2 = new Consumidor("Consumidor 2", a);
        p.start();
        c1.start();
        c2.start();
    }
}

public class SumaMatrices {
    static int[][] a = {{1,2,3},{4,5,6},{7,8,9}};
    static int[][] b = {{9,8,7},{6,5,4},{3,2,1}};
    static int[][] resultado = new int[3][3];

    static class HiloSuma extends Thread {
        private final int fila, columna;

        HiloSuma(int fila, int columna) {
            this.fila = fila;
            this.columna = columna;
        }

        @Override
        public void run() {
            resultado[fila][columna] = a[fila][columna] + b[fila][columna];
        }
    }

    public static void main(String[] args) throws InterruptedException {
        Thread[][] hilos = new Thread[3][3];

        for (int i = 0; i < 3; i++) {
            for (int j = 0; j < 3; j++) {
                hilos[i][j] = new HiloSuma(i, j);
                hilos[i][j].start();
            }
        }

        for (int i = 0; i < 3; i++)
            for (int j = 0; j < 3; j++)
                hilos[i][j].join();

        for (int[] fila : resultado) {
            for (int valor : fila) System.out.print(valor + " ");
            System.out.println();
        }
    }
}

public class MonitorReloj {
    private int turno = 0;

    public synchronized void imprimir(int miTurno, String texto) {
        for (int i = 0; i < 10; i++) {
            while (turno != miTurno) {
                try {
                    wait();
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                    return;

            notifyAll();
        }
    }
}

        new Thread(() -> monitor.imprimir(2, "TOC")).start();

Repaso 12. Sala de ordenadores: máximo tres alumnos

Diez alumnos comparten tres ordenadores. Los que llegan cuando los tres están ocupados esperan.

SOLUCIONES DEL REPASO

Código de referencia para este ejercicio. Revisa la solución y adapta los nombres de las clases y de los componentes a lo que pide el enunciado. 

// SalaOrdenadores.java
public class SalaOrdenadores {
    private int ocupados = 0;
    private final int capacidad = 3;

    public synchronized void entrar(String alumno) throws InterruptedException {
        while (ocupados == capacidad) {
            System.out.println(alumno + " espera un ordenador");
            wait();
        }
        ocupados++;
        System.out.println(alumno + " entra. Ocupados: " + ocupados);
    }

    public synchronized void salir(String alumno) {
        ocupados--;
        System.out.println(alumno + " sale. Ocupados: " + ocupados);
        notifyAll();
    }
}

// Alumno.java
class Alumno extends Thread {
    private final SalaOrdenadores sala;

    Alumno(String nombre, SalaOrdenadores sala) {
        super(nombre);
        this.sala = sala;
    }

    @Override
    public void run() {
        try {
            sala.entrar(getName());
            Thread.sleep(2000);
            sala.salir(getName());
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
    }
}

// PrincipalSala.java
public class PrincipalSala {
    public static void main(String[] args) {
        SalaOrdenadores sala = new SalaOrdenadores();
        for (int i = 1; i <= 10; i++) {
            new Alumno("Alumno " + i, sala).start();
        }
    }
}

Claves para el examen

  • start() inicia un hilo nuevo; llamar a run() directamente no lo hace.
  • synchronized protege el recurso solo si los hilos comparten el mismo objeto monitor.
  • wait() y notifyAll() se ejecutan dentro de código sincronizado sobre el mismo monitor.
  • Usa siempre while para comprobar la condición después de despertar de wait().
  • sleep() pausa el hilo, pero no libera el monitor que ya posee.
  • join() permite esperar a que otro hilo termine.

Tips, Reglas de Oro y Errores Típicos

Colección de pautas esenciales para superar el examen práctico de PSP y evitar fallos clásicos de concurrencia en la JVM.

Reglas de Oro de Sincronización

  • 1. `wait()` SIEMPRE dentro de un bucle `while`: Nunca uses un `if`. Cuando un hilo despierta, la condición de espera podría haber dejado de cumplirse por la acción de otro hilo.
  • 2. Prefiere `notifyAll()` sobre `notify()`: `notify()` despierta a un hilo indeterminado. Si despierta al hilo equivocado, el sistema puede quedar bloqueado permanentemente.
  • 3. `sleep()` no libera cerrojos; `wait()` SI los libera: Si duermes a un hilo con `Thread.sleep()` dentro de un bloque sincronizado, mantendrá el cerrojo bloqueando a los demás.

Errores Típicos a Evitar

  • 1. Invocación directa a `run()` en lugar de `start()`: Si llamas a `hilo.run()`, el código se ejecutará secuencialmente en el hilo principal y NO en una nueva hebra concurrente.
  • 2. Usar `wait()` o `notify()` fuera de `synchronized`: Lanzará la excepción runtime IllegalMonitorStateException en tiempo de ejecución.
  • 3. Sincronizar objetos distintos: Para que la exclusión mutua funcione entre dos hilos, ambos deben sincronizarse exactamente sobre la misma referencia de objeto.
