Acceso a Datos - Unidad de Trabajo 3

Manejo de Conectores: Bases de Datos Relacionales y Arquitectura JDBC

1. Introducción y el Desfase Objeto-Relacional

Acceso a Datos: Es el proceso de recuperación o manipulación de datos procedentes de orígenes locales o remotos, tales como bases de datos relacionales, hojas de cálculo, ficheros de texto o servicios web.

El Desfase Objeto-Relacional (Object-Relational Impedance Mismatch): Aunque las bases de datos relacionales dominan el mercado por su rendimiento y flexibilidad, el paradigma imperante de desarrollo de software es la Programación Orientada a Objetos (POO). Dado que las bases de datos relacionales no fueron concebidas para almacenar objetos directamente, surge una disparidad estructural que exige un esfuerzo de programación adicional para adaptar las tablas relacionales a las clases y objetos.

2. Concepto de Conector y Arquitectura de Drivers

Los Sistemas Gestores de Bases de Datos (SGBD) operan mediante lenguajes especializados como SQL, mientras que las aplicaciones cliente se programan en lenguajes de propósito general como Java. Los conectores proporcionan una API común que permite a estos programas comunicarse de forma transparente con los SGBD.

El conector define una arquitectura donde la interfaz es unificada, mientras que los drivers se encargan de gestionar las particularidades sintácticas y de red de cada motor específico.

Representación conceptual: Arquitectura de Conectores y Drivers
[ Programa de Aplicación (Java) ]
              │
              ▼
       [ Conector (API) ]
              │
    ┌─────────┼─────────┐
    ▼         ▼         ▼
[Driver 1] [Driver 2] [Driver 3]
    │         │         │
    ▼         ▼         ▼
 [SGBD 1]  [SGBD 2]  [SGBD 3]

Principales Arquitecturas de Conexión:

  • ODBC (Open Database Connectivity): Especificación escrita en C para conectar aplicaciones con motores SQL compatibles.
  • JDBC (Java Database Connectivity): El estándar por antonomasia de Java para enlazar programas con bases de datos relacionales.
  • Otras arquitecturas históricas/propietarias: OLE-DB y ADO.
3. Modelos de Acceso y Tipos de Drivers en JDBC

3.1. Modelos de Acceso

  • Modelo de dos capas (Cliente/Servidor): La aplicación Java se comunica directamente con la base de datos a través del driver JDBC residente en su mismo entorno de ejecución. El SGBD procesa las sentencias SQL y devuelve los resultados directamente.
  • Modelo de tres capas: Las peticiones de la aplicación cliente se envían a un servidor de aplicaciones o capa intermedia encargada de gestionar los comandos SQL contra el motor de la base de datos y recolectar los datos.

3.2. Clasificación de Drivers JDBC

Tipo de Driver Descripción y Mecanismo
Tipo 1: Puente JDBC-ODBC Permite el acceso a SGBD JDBC mediante el protocolo ODBC.
Tipo 2: API Nativa Controlador escrito parcialmente en Java y en código nativo de bases de datos que traduce las llamadas de la API a llamadas del SGBD.
Tipo 3: Protocolo de Red Controlador de Java puro que utiliza un protocolo de red independiente para comunicarse con un servidor intermedio.
Tipo 4: Thin Driver (Protocolo Nativo) Controlador de Java puro con protocolo nativo que traduce llamadas de la API directamente al protocolo de red del SGBD.

5. Ciclo de Vida y Ejecución de Consultas JDBC

El ciclo de vida estándar de una operación JDBC consta de las siguientes etapas secuenciales:

  1. Importar las clases necesarias del paquete java.sql.
  2. Cargar el Driver JDBC en memoria mediante Class.forName().
  3. Establecer el objeto Connection a través de DriverManager.getConnection().
  4. Crear un objeto de ejecución Statement desde la conexión activa.
  5. Ejecutar la consulta SQL llamando a sentencia.executeQuery().
  6. Recuperar y procesar las tuplas del ResultSet mediante el cursor secuencial next() y métodos getXXX().
  7. Liberar los recursos explícitamente cerrando ResultSet, Statement y Connection con close().
Código Ejemplo: Consulta de Departamentos en MySQL con JDBC
import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.ResultSet;
import java.sql.SQLException;
import java.sql.Statement;

public class ConsultaJDBC {
    public static void selectMySQL() {
        try {
            // 1. Cargar el driver
            Class.forName("com.mysql.cj.jdbc.Driver");
            
            // 2. Establecer la conexión con la base de datos
            Connection conexion = DriverManager.getConnection("jdbc:mysql://localhost/empresa", "root", "");
            
            // 3. Preparar la consulta
            Statement sentencia = conexion.createStatement();
            String sql = "SELECT * FROM departamentos";
            ResultSet resultado = sentencia.executeQuery(sql);
            
            // 4. Recorrer el resultado para visualizar cada fila
            while (resultado.next()) {
                System.out.println(resultado.getInt(1) + " " + resultado.getString(2) + " " + resultado.getString(3));
            }
            
            // 5. Cierre de recursos
            resultado.close();
            sentencia.close();
            conexion.close();
        } catch (ClassNotFoundException e) {
            e.printStackTrace();
        } catch (SQLException e) {
            e.printStackTrace();
        }
    }

    public static void main(String[] args) {
        selectMySQL();
    }
}

Sentencias DML y DDL en JDBC: Manipulación y Definición de Datos

6. Ejecución de Sentencias DML (Data Manipulation Language)

Las sentencias DML permiten operar directamente con los datos almacenados en una base de datos relacional:

  • SELECT: Para obtener o consultar datos.
  • INSERT: Para añadir nuevos registros a una tabla.
  • UPDATE: Para modificar registros existentes.
  • DELETE: Para eliminar registros sin destruir la estructura de la tabla.

6.1. Métodos de Ejecución de la Interfaz Statement

Método Descripción de Funcionamiento
ResultSet executeQuery(String query) Ejecuta consultas de selección y devuelve un objeto ResultSet con los datos recuperados.
int executeUpdate(String query) Ejecuta sentencias DML de modificación (INSERT, UPDATE, DELETE) y devuelve un entero con el número de filas afectadas.
boolean execute(String query) Permite ejecutar cualquier instrucción SQL. Si devuelve un ResultSet retorna true (obteniéndose con getResultSet()); en caso contrario retorna false (obteniéndose el recuento de filas con getUpdateCount()).

6.2. Sentencias Preparadas (PreparedStatement)

Para consultas con parámetros variables se utiliza PreparedStatement. Emplea marcadores de posición o placeholders representados con signos de interrogación (?) que se indexan a partir de 1. La precompilación de la sentencia aporta seguridad, evita inyecciones SQL y permite ejecutar la misma consulta múltiples veces de manera eficiente.

Métodos de Asignación por Tipos SQL

Método de Asignación Java Tipo Equivalente en SQL
setString(int index, String valor) VARCHAR
setInt(int index, int valor) INTEGER
setFloat(int index, float valor) FLOAT
setDouble(int index, double valor) DOUBLE
setDate(int index, Date valor) DATE
setBoolean(int index, boolean valor) BIT
setBytes(int index, byte[] valor) VARBINARY
Código Ejemplo: Inserción de Datos con PreparedStatement
// Definición de consulta parametrizada con placeholders
String sql = "INSERT INTO empleados (emp_no, apellido, oficio, fecha_alt, salario, dept_no) "
           + "VALUES (?, ?, ?, ?, ?, ?)";

PreparedStatement sentenciaPreparada = conexion.prepareStatement(sql);
sentenciaPreparada.setInt(1, 20);
sentenciaPreparada.setString(2, "FERNANDEZ");
sentenciaPreparada.setString(3, "ANALISTA");
sentenciaPreparada.setDate(4, new java.sql.Date(System.currentTimeMillis()));
sentenciaPreparada.setFloat(5, 1500f);
sentenciaPreparada.setInt(6, 40);

int filasAfectadas = sentenciaPreparada.executeUpdate();
System.out.println("Registros insertados: " + filasAfectadas);

sentenciaPreparada.close();
conexion.close();

6.3. Procesamiento Avanzado con ResultSet

El acceso a los datos de la tupla activa puede realizarse tanto por índice numérico (comenzando en 1) como mediante el nombre de la columna:

  • Extracción posicional: resultado.getString(1) o resultado.getDouble(2).
  • Extracción nominal: resultado.getString("nombre") o resultado.getDouble("salario").
  • Inspección estructural: el método resultado.getMetaData() permite recuperar metadatos como el número o tipo de las columnas devueltas.
7. Ejecución de Sentencias DDL y Metadatos de la Base de Datos

7.1. Definición y Modificación de Estructuras (DDL)

Aunque el trabajo diario suele ser DML, las instrucciones DDL (como CREATE TABLE o ALTER TABLE) son esenciales para inicializar esquemas en instalaciones limpias o aplicar migraciones tras actualizaciones. Se ejecutan mediante llamadas al método executeUpdate() de un objeto Statement.

Código Ejemplo: Creación Dinámica de Tablas con DDL
Connection conexion = DriverManager.getConnection("jdbc:mysql://localhost/animales", "root", "");
Statement sentencia = conexion.createStatement();

String sql = "CREATE TABLE IF NOT EXISTS mascotas ("
           + "codigo VARCHAR(3), "
           + "nombre VARCHAR(20), "
           + "CONSTRAINT mascotas_PK PRIMARY KEY (codigo)"
           + ");";

int resultado = sentencia.executeUpdate(sql);
System.out.println("Resultado de ejecución DDL: " + resultado);

sentencia.close();
conexion.close();

7.2. Inspección del Esquema con DatabaseMetaData

Cuando se desconoce la estructura física de la base de datos, se recurre a la interfaz DatabaseMetaData obtenida desde la conexión activa mediante conexion.getMetaData().

Métodos Principales de DatabaseMetaData

Método Información Recuperada
ResultSet getTables(...) Proporciona información sobre objetos del esquema (tablas, vistas, alias, tablas del sistema).
ResultSet getColumns(...) Devuelve las columnas, tipos y configuraciones de una tabla específica.
ResultSet getPrimaryKeys(...) Lista los campos que componen la clave primaria.
ResultSet getExportedKeys(...) Devuelve las claves foráneas que apuntan hacia una tabla.
ResultSet getImportedKeys(...) Devuelve las claves foráneas que la tabla importa de otras tablas.
Código Ejemplo: Listado de Tablas y Vistas mediante DatabaseMetaData
DatabaseMetaData dbmd = conexion.getMetaData();
String[] tipos = {"TABLE", "VIEW"};

// Parámetros: catálogo (null=actual), esquema (null=actual), patrón tabla (null=todas), tipos
ResultSet tablas = dbmd.getTables(null, null, null, tipos);

while (tablas.next()) {
    String catalogo = tablas.getString("TABLE_CAT");
    String esquema  = tablas.getString("TABLE_SCHEM");
    String nombre   = tablas.getString("TABLE_NAME");
    String tipo     = tablas.getString("TABLE_TYPE");

    System.out.println("Objeto: " + nombre + " | Tipo: " + tipo + " | Catálogo: " + catalogo);
}

tablas.close();

Procedimientos y Funciones Almacenadas en JDBC

8. Fundamentos y Creación de Procedimientos

Definición: Un procedimiento almacenado consiste en un conjunto de instrucciones SQL compiladas y almacenadas en el propio motor de la base de datos, invocables por su nombre para llevar a cabo alguna tarea.

Tipos de Parámetros: Pueden definirse con parámetros de entrada (IN), de salida (OUT), de entrada/salida combinada (INOUT) o sin ningún parámetro. Si la rutina devuelve directamente un valor computable, se cataloga técnicamente como una función.

Definición SQL: Procedimiento subida_sal y delimitadores en MySQL
DELIMITER //
CREATE PROCEDURE subida_sal (d INT, subida INT)
BEGIN
    UPDATE empleados SET salario = salario + subida WHERE dept_no = d;
    COMMIT;
END//
DELIMITER ;

Nota sobre DELIMITER: En la consola de MySQL o scripts externos se sustituye temporalmente el carácter de terminación ; por // para evitar que el intérprete finalice la instrucción prematuramente al encontrar el primer punto y coma interno del cuerpo del procedimiento.

8.1. Creación Programática de Procedimientos desde Java

Mediante un objeto Statement es posible emitir sentencias DDL para registrar o sustituir procedimientos almacenados en la base de datos directamente desde código Java:

Código Ejemplo: Creación de Procedimiento subida_sal con Statement
public static void crearProcedimientoSalario() {
    try {
        Class.forName("com.mysql.cj.jdbc.Driver");
        Connection conexion = DriverManager.getConnection("jdbc:mysql://localhost/empresa", "root", "");
        Statement statement = conexion.createStatement();

        String queryDrop = "DROP PROCEDURE IF EXISTS subida_sal;";
        String queryCreate = "CREATE PROCEDURE subida_sal (IN d INT, IN subida INT) "
                           + "BEGIN "
                           + "UPDATE empleados SET salario = salario + subida WHERE dept_no=d; "
                           + "END";

        statement.execute(queryDrop);
        statement.execute(queryCreate);
        System.out.println("Procedimiento creado");

        statement.close();
        conexion.close();
    } catch (ClassNotFoundException | SQLException e) {
        e.printStackTrace();
    }
}
9. Invocación desde Java con CallableStatement

La interfaz CallableStatement permite que se pueda llamar desde Java a los procedimientos y funciones almacenadas. Para crear un objeto se llama al método prepareCall(String) del objeto Connection, empleando marcadores de posición (?) para suministrar los argumentos.

9.1. Sintaxis Estándar de Escape para Llamadas

Formato de Declaración Caso de Uso y Descripción
{call procedimiento} Para un procedimiento almacenado sin parámetros.
{call procedimiento(?, ?, ...)} Para un procedimiento almacenado que recibe parámetros posicionales.
{? = call funcion} Para una función almacenada que devuelve un valor (a la izquierda del igual, primer parámetro) y no recibe argumentos.
{? = call funcion(?, ?, ...)} Para una función almacenada que devuelve un valor (primer parámetro) y recibe varios parámetros.

9.2. Código Ejemplo: Ejecución de Procedimiento con Parámetros IN

Código: Subida de Salario con Parámetros de Entrada
public static void SubidaSalarioEmpleados(int dep, double subida) {
    try {
        Class.forName("com.mysql.cj.jdbc.Driver");
        Connection conexion = DriverManager.getConnection("jdbc:mysql://localhost/empresa", "root", "");
        
        // 1. Preparación de la llamada con marcadores posicionales (?)
        String sql = "{call subida_sal(?, ?)}";
        CallableStatement cst = conexion.prepareCall(sql);
        
        // 2. Damos valor a los argumentos IN según su índice
        cst.setInt(1, dep);
        cst.setDouble(2, subida);
        
        // 3. Ejecución del procedimiento
        cst.executeUpdate();
        System.out.println("Subida realizada....");
        
        cst.close();
        conexion.close();
    } catch (ClassNotFoundException | SQLException e) {
        e.printStackTrace();
    }
}

9.3. Consulta y Recorrido de Resultados Devueltos por Procedimientos

Cuando un procedimiento ejecuta internamente una consulta SELECT (como get_departamentos()), el objeto CallableStatement se ejecuta mediante executeQuery() y retorna un objeto ResultSet para procesar las filas resultantes.

Código Ejemplo: Obtención de ResultSet mediante CallableStatement
public static void getDepartamentosMySQL() {
    try {
        Class.forName("com.mysql.cj.jdbc.Driver");
        Connection conexion = DriverManager.getConnection("jdbc:mysql://localhost/empresa", "root", "");
        
        String sql = "{call get_departamentos()}";
        CallableStatement cst = conexion.prepareCall(sql);
        ResultSet rs = cst.executeQuery();
        
        while (rs.next()) {
            System.out.println("Codigo: " + rs.getString(1));
            System.out.println("Departamento: " + rs.getString(2));
        }
        
        cst.close();
        rs.close();
        conexion.close();
    } catch (ClassNotFoundException | SQLException e) {
        e.printStackTrace();
    }
}
10. Gestión de Parámetros de Salida (OUT e INOUT)

Cuando un procedimiento o función cuenta con parámetros de salida (OUT), estos deben ser registrados obligatoriamente antes de que la llamada tenga lugar para evitar que se produzca un error.

10.1. Registro y Extracción

  • Registro: Se utiliza el método cst.registerOutParameter(índice, tipoJDBC). El primer parámetro representa la posición y el segundo es una constante genérica SQL definida en la clase java.sql.Types (ej.: Types.VARCHAR, Types.INTEGER, Types.DOUBLE, Types.FLOAT).
  • Extracción: Una vez ejecutada la llamada con executeUpdate(), los valores devueltos por los parámetros OUT e INOUT se obtienen mediante los métodos getXXX(índice).
Definición SQL: Procedimiento localidad_depart con Parámetro OUT
CREATE PROCEDURE localidad_depart (IN d INT, OUT localidad VARCHAR(15))
BEGIN
    SELECT loc INTO localidad FROM departamentos WHERE dept_no = d;
END;
Código Ejemplo: Registro y Lectura de Parámetro OUT en Java
public static void obtenerLocalidad(int dep) {
    try {
        Class.forName("com.mysql.cj.jdbc.Driver");
        Connection conexion = DriverManager.getConnection("jdbc:mysql://localhost/empresa", "root", "");
        
        String sql = "{call localidad_depart(?, ?)}";
        CallableStatement cst = conexion.prepareCall(sql);
        
        // Damos valor al argumento de entrada (IN)
        cst.setInt(1, dep);
        
        // Registro obligatorio del argumento de salida (OUT)
        cst.registerOutParameter(2, java.sql.Types.VARCHAR);
        
        // Ejecutar el procedimiento
        cst.executeUpdate();
        
        // Recuperación del resultado con getXXX()
        System.out.println("Localidad: " + cst.getString(2));
        
        cst.close();
        conexion.close();
    } catch (ClassNotFoundException | SQLException e) {
        e.printStackTrace();
    }
}
