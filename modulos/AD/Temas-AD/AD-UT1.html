1. Introducción

Memoria vs. Persistencia: Los programas utilizan variables para almacenar información en memoria (datos de entrada, resultados intermedios, etc.), pero estos datos son efímeros y desaparecen al finalizar la ejecución. Cuando se necesita almacenar datos permanentemente, se recurre a soportes de almacenamiento persistente en forma de ficheros o bases de datos (las cuales internamente también se apoyan en archivos).

Clasificación de los ficheros:

  • Por contenido:
    • Texto (caracteres): Contienen únicamente caracteres legibles a través de un editor de texto convencional.
    • Binarios (bytes): Almacenan secuencias de bytes que representan cualquier tipo de dato (números, sonido, imágenes, ejecutables, etc.).
  • Por modo de acceso:
    • Secuenciales: La información se organiza de forma secuencial; para acceder al byte i-ésimo es forzoso haber leído previamente todos los anteriores.
    • Acceso directo o aleatorio: Permite posicionarse y leer/escribir directamente en el byte i-ésimo sin procesar los anteriores.

Paquetes en Java: Las clases principales para el manejo de archivos se localizan en los paquetes java.io y java.nio.file.

Representación textual: Jerarquía de clases de java.io (Diagrama)

A partir de la clase base Object de java.lang, se despliegan en java.io:

  • Clases independientes/auxiliares: File, FileDescriptor, RandomAccessFile (implementa DataInput y DataOutput), FilenameFilter (interfaz) y ObjectStreamClass.
  • Rama InputStream (flujo de entrada de bytes): ByteArrayInputStream, FileInputStream, FilterInputStream (de la que derivan: BufferedInputStream, DataInputStream, LineNumberInputStream, PushbackInputStream), ObjectInputStream (implementa DataInput), PipedInputStream, SequenceInputStream, StringBufferInputStream.
  • Rama OutputStream (flujo de salida de bytes): ByteArrayOutputStream, FileOutputStream, FilterOutputStream (de la que derivan: BufferedOutputStream, DataOutputStream, PrintStream), ObjectOutputStream (implementa DataOutput), PipedOutputStream.

2. La clase File

Proporciona utilidades para obtener información de archivos y directorios del sistema de ficheros (nombre, atributos, rutas, etc.). Un objeto File puede representar un archivo físico concreto, una colección de archivos dentro de un directorio o un directorio nuevo pendiente de creación.

  • Constructores:
    • File(String rutaCompleta) → Ejemplo: new File("./resources/textFiles/file001.txt");
    • File(String rutaDirectorio, String nombreArchivo) → Ejemplo: new File("./resources/textFiles", "file001.txt");
  • Rutas según el Sistema Operativo:
    • Windows: Usa barras invertidas escapadas ("C:\\Users\\Admin\\DocumentsandFiles\\file001.txt").
    • Sistemas tipo Unix (Linux, macOS, Android): Emplea barras inclinadas ("/Users/Admin/DocumentsandFiles/file001.txt").

3. Flujos o Streams

Un Stream es la abstracción empleada en Java para canalizar la transferencia de datos entre una fuente (disco duro, memoria principal, red, otro proceso) y un destino. Por defecto operan en serie.

Representación del flujo: [Data Source] → [Stream de Bytes / Bits] → [Programa Java].

  • Flujos de Bytes (8 bits): Orientados a operaciones de E/S binarias. Todas las clases derivan de InputStream y OutputStream.
  • Flujos de Caracteres (16 bits): Orientados a caracteres y texto (soporte para caracteres Unicode de 16 bits). Derivan de las clases abstractas Reader y Writer.

  • Rama Reader: BufferedReader, CharArrayReader, InputStreamReader → de la cual deriva directamente FileReader, FilterReader, PipedReader, StringReader.

  • OutputStreamWriter: Convierte flujos de salida de bytes (OutputStream) en flujos de caracteres (Writer).

4. Formas de acceso y operaciones

  • Acceso secuencial: Los datos se leen y escriben en estricto orden progresivo. Para leer el dato N es imprescindible leer los N-1 anteriores. Las inserciones siempre van al final.
  • Acceso directo o aleatorio: Permite acceder a cualquier byte o registro conociendo su posición o tamaño mediante cálculos de desplazamiento sin recorrer el resto.

Operaciones sobre ficheros: Creación, apertura, lectura, escritura y cierre.

Gestión sobre datos (CRUD):

  • En ficheros secuenciales:
    • Consulta: Lectura secuencial desde el inicio hasta dar con el registro.
    • Alta: Siempre al final del fichero.
    • Bajas y Modificaciones: Obligan a procesar el fichero volcando todos los registros (excepto el que se borra o actualiza) a un fichero auxiliar temporal, para luego eliminar el original y renombrar el auxiliar.
  • En ficheros aleatorios:
    • Se utiliza una función de conversión basada en la clave y tamaño de registro (ej.: para clave autonómica N, posición = tamaño * (N - 1)).
    • Bajas: Pueden ser lógicas (marca booleana de activo/eliminado) o físicas (eliminación real).

Se gestionan a través de FileReader y FileWriter, requiriendo control de excepciones (FileNotFoundException e IOException).

  • false (por defecto): Trunca y sobrescribe el contenido previo.

  • BufferedReader: Incluye el método readLine() para leer líneas completas de texto (retorna null en EOF); envuelve un FileReader.

  • PrintWriter: Aporta métodos de alto nivel equivalentes a consola (print() y println()), envolviendo un flujo como FileWriter.

1. Ficheros binarios en Java

Guardan directamente la representación interna en bits; no son legibles de forma directa con un editor de texto plano y optimizan el espacio en disco.

Las clases base de E/S son FileInputStream (lectura) y FileOutputStream (escritura).

Modo Append: Al igual que en texto, new FileOutputStream(f, true) preserva la información existente.

2. Flujos de datos primitivos (DataInputStream / DataOutputStream)

Concepto de envoltorio (Wrapper): FileInputStream y FileOutputStream solo procesan secuencias de bytes crudos. Para trabajar directamente con tipos nativos (int, float, boolean, cadenas UTF, etc.) sin gestionar la conversión de bits a mano, se envuelve el flujo en DataInputStream o DataOutputStream.

Representación conceptual: Wrapping de flujos (Diagrama)
  • Lectura: [InputStream crudo (read())] → Envuelto por → [DataInputStream (readInt(), readFloat(), readLong()...)]
  • Escritura: [DataOutputStream (writeInt(), writeFloat(), writeLong()...)] → Envuelve a → [OutputStream crudo (write())]

Detección de Fin de Fichero: Al leer con DataInputStream, el fin del archivo no devuelve -1, sino que lanza la excepción EOFException. La estructura canónica consiste en encerrar la lectura en un bucle infinito do { ... } while(true); dentro de un bloque try-catch (EOFException e) para proceder al cierre del flujo en la captura.

3. Persistencia de Objetos (ObjectInputStream / ObjectOutputStream)

Permite guardar y recuperar instancias de clases completas en formato binario mediante serialización, evitando tener que descomponer el objeto atributo por atributo.

  • Requisito indispensable: La clase del objeto a persistir debe implementar la interfaz Serializable (del paquete java.io).
  • Lectura y escritura:
    • oos.writeObject(objeto): Serializa y escribe el objeto.
    • (TipoClase) ois.readObject(): Lee y deserializa el objeto (requiere capturar ClassNotFoundException y EOFException).

La problemática de la cabecera (Header Corrupted):

  • Cada vez que se crea una nueva instancia de ObjectOutputStream, Java inyecta automáticamente una cabecera binaria inicial con metainformación.
  • Si se abre un fichero existente para añadir objetos en modo append, se volverá a incrustar una cabecera intermedia entre los objetos ya guardados y los nuevos.
  • Al leer el fichero secuencialmente con ObjectInputStream, al topar con esa cabecera secundaria en mitad del flujo se lanza un error de tipo StreamCorruptedException.

Solución técnica:

Crear una subclase personalizada derivada de ObjectOutputStream (por ejemplo, MyObjectOutputStream) sobrescribiendo el método writeStreamHeader() para dejarlo completamente vacío:

public class MyObjectOutputStream extends ObjectOutputStream {
    public MyObjectOutputStream(OutputStream out) throws IOException {
        super(out);
    }
    @Override
    protected void writeStreamHeader() throws IOException {
        // Se deja vacío para no duplicar cabeceras en archivos ya creados
    }
}

Al abrir el archivo para escritura, comprobar si existe mediante f.exists(): si el archivo no existe se usa ObjectOutputStream estándar (para escribir la cabecera requerida); si ya existe, se instancia MyObjectOutputStream.

4. Ficheros de acceso aleatorio (RandomAccessFile)

Permite el posicionamiento libre dentro de un archivo mediante un puntero de lectura/escritura sin estar obligado a recorrer los registros previos.

  • Constructores y modos: RandomAccessFile(String ruta, String modo) o RandomAccessFile(File f, String modo). Modos: "r" (solo lectura) y "rw" (lectura y escritura).

Cálculo de tamaño de un registro compuesto (Caso del documento):

  • Campo id (int): 4 bytes
  • Campo apellido (fijado a 10 char usando StringBuffer.setLength(10)): 10 × 2 = 20 bytes
  • Campo departamento (int): 4 bytes
  • Campo salario (double): 8 bytes
  • Tamaño total del registro: 4 + 20 + 4 + 8 = 36 bytes.

Fórmula de acceso posicional:

Posición = (N - 1) × tamañoRegistro

Ejemplo: para el empleado con ID 5 con registros de 36 bytes, el cursor se posiciona en:

raf.seek((5 - 1) * 36); // Posiciona el puntero en el byte 144
