Método Callback Estado Resultante Momento de Ejecución y Propósito

onStart() Pausada La actividad pasa a ser visible para el usuario.

TEMA 3: Introducción al Lenguaje de Programación Kotlin

1. Fundamentos e Historia de Kotlin

Kotlin es un lenguaje de programación moderno, conciso y fuertemente tipado desarrollado por JetBrains a partir de 2010. Surgió ante la necesidad de JetBrains de optimizar la inmensa base de código de sus propios IDEs (como IntelliJ IDEA, escrito en Java), buscando un lenguaje más limpio y productivo sin abandonar el entorno de la Máquina Virtual de Java (JVM). Tras descartar Scala por cuestiones de eficiencia y tiempos de compilación, crearon su propia solución, presentada como lenguaje oficial para Android por Google en Google I/O 2017.

  • Multiplataforma: Compila para JVM, JavaScript y código binario nativo (Kotlin/Native).
  • Sintaxis concisa: Reduce drásticamente el código repetitivo (boilerplate) en comparación con Java.
  • Interoperabilidad 100%: Puede convivir e interactuar perfectamente con proyectos y librerías en Java.
  • Null Safety: Mecanismo integrado a nivel de tipos para erradicar las excepciones NullPointerException.
  • Empresas que lo utilizan: Google, Netflix, Twitter/X, Pinterest, Uber, Airbnb, Expedia, American Express, Slack, Trello, Evernote, Reddit, etc.

2. Uso de Logcat en Android Studio

Logcat es la herramienta de consola de Android Studio encargada de volcar el registro de mensajes del sistema y de las aplicaciones. Se abre desde View → Tool Windows → Logcat. La emisión de mensajes se realiza mediante la clase android.util.Log, pasando dos parámetros obligatorios: la etiqueta o identificador (tag: String?) y el texto (msg: String).

  • Log.v("TAG", "Verbose"): Nivel de depuración minuciosa (prioridad más baja).
  • Log.d("TAG", "Debug"): Información relevante para depuración en desarrollo.
  • Log.i("TAG", "Info"): Notificaciones habituales del ciclo operativo.
  • Log.w("TAG", "Warning"): Alertas sobre posibles anomalías que no detienen la ejecución.
  • Log.e("TAG", "Error"): Errores críticos y excepciones en tiempo de ejecución.
  • Log.wtf("TAG", "Fatal"): Fallo gravísimo ("What a Terrible Failure").
  • Filtros y Búsqueda: En la barra de Logcat se puede filtrar por paquete (package:mine o com.example.app), por nivel (level:debug) o buscar con Ctrl + F.

3. Sintaxis Básica de Kotlin

Comentarios, Variables y Constantes

Se comenta una línea con // y bloques con /* ... */. Las variables mutables se declaran con var y las constantes (inmutables una vez asignadas) con val. Permiten inferencia estática de tipos:

val nombre: String = "Pepe" // Constante inmutable con tipo explícito
var edad = 25                // Variable mutable con inferencia de tipo Int
Log.d("TAG", "Nombre: $nombre, Edad: $edad") // String templates con interpolación $
Log.d("TAG", "Edad en texto: ${edad.toString()}")

Plantillas de Cadenas (String Templates) e Interpolación con $ y ${...}

En Kotlin no es necesario concatenar con el operador + para incrustar variables o expresiones calculadas dentro de un texto. Se utiliza el símbolo $ (String Templates):

  • Variable directa ($variable): Sustituye el identificador por el valor actual de la variable. Ejemplo: "Hola $nombre" o "Contador: $count".
  • Expresiones y cálculos (${expresión}): Cuando queremos realizar un cálculo aritmético, acceder a propiedades, llamar a funciones o evaluar expresiones lógicas directamente dentro del texto, se encierra entre llaves precedidas del dólar ${...} para que se compute y muestre el resultado evaluado.
val num1 = 10
val num2 = 5

// 1. Interpolación simple de variables:
Log.d("TAG", "Primer número: $num1, Segundo número: $num2")

// 2. Interpolación con operaciones y cálculos directos dentro de ${}:
Log.d("TAG", "La suma calculada es: ${num1 + num2}")         // Muestra: 15
Log.d("TAG", "El doble del primer número es: ${num1 * 2}")    // Muestra: 20
Log.d("TAG", "La longitud del nombre es: ${nombre.length}")   // Muestra: 4
Log.d("TAG", "Resultado condicional: ${if (num1 > num2) "Mayor" else "Menor"}")

// 3. Uso en Text de Jetpack Compose:
Text(text = "El total calculado es: ${precio * 1.21} €")
Text(text = "${stringResource(id = R.string.seleccionado_text)}: $seleccion")

Tipos de Datos Primitivos

  • Enteros: Byte (8 bits, -128 a 127), Short (16 bits, -32768 a 32767), Int (32 bits), Long (64 bits, ej. 100L).
  • Decimales: Float (32 bits, sufijo f o F, ej. 1.73f), Double (64 bits, hasta 16 decimales).
  • Otros: Boolean (true / false), Char (carácter entre comillas simples, ej. 'A'), String (cadenas de texto).

Operadores

  • Aritméticos: +, -, *, /, % (módulo).
  • Incremento y Decremento: ++, --.
  • Relacionales: ==, !=, <, >, <=, >=.
  • Lógicos: && (AND), || (OR), ! (NOT).

Null Safety (Seguridad frente a Nulos)

Por defecto, ningún tipo admite valores null. Para permitir que una variable contenga null se añade el modificador ? detrás de su tipo. Para operar de forma segura con variables nulables se emplea el operador de llamada segura ?. combinado con let y el operador Elvis ?::

var password: String? = null

password?.let {
    Log.d("TAG", "Password introducido: $it")
} ?: run {
    Log.d("TAG", "La variable password no tiene valor o es nula")
}

Funciones

Se definen con fun. Los parámetros siguen la estructura nombre: Tipo. Si no devuelven nada retornan Unit (omisible). Si constan de una sola expresión, admiten sintaxis en línea:

// Sintaxis tradicional
private fun calcularDoble(numero: Int): Int {
    return numero * 2
}

// Sintaxis de expresión única simplificada
private fun calcularDobleSimple(numero: Int): Int = numero * 2

Clases, Propiedades, Getters/Setters y Constructores

Kotlin genera automáticamente los métodos getter y setter entre bastidores (utilizando la palabra clave interna field para evitar recursión infinita). Admite constructores primarios en la cabecera y secundarios dentro del cuerpo con constructor(...) : this(...):

class Persona(var nombre: String, var edad: Int) {
    var telefono: Int = 111222333

    // Constructor secundario delegando en el primario mediante this
    constructor(nombre: String, edad: Int, nuevoTelefono: Int) : this(nombre, edad) {
        this.telefono = nuevoTelefono
    }

    // Personalización de setter
    var salario: Double = 1000.0
        set(value) {
            field = if (value >= 1000.0) value else 1000.0
        }

    fun presentacion() {
        Log.d("TAG", "Soy $nombre, tengo $edad años y teléfono $telefono")
    }
}

Data Classes e Interfaces

Las data class están diseñadas para transportar datos; generan automáticamente métodos equals(), hashCode(), toString() y copy(). Las interface definen contratos de comportamiento que las clases implementan con override:

data class ProgrammerData(val name: String, val age: Int, val language: String)

interface ProgramadorInterface {
    fun getProgrammerData(): ProgrammerData
}

class Programador(private val nom: String, private val ed: Int, private val lang: String) : ProgramadorInterface {
    override fun getProgrammerData(): ProgrammerData {
        return ProgrammerData(nom, ed, lang)
    }
}

4. Colecciones en Kotlin

  • Listas Inmutables (List): Creadas con listOf("A", "B", "C"). Métodos: size, get(index) o [index], indexOf(elem), contains(elem).
  • Listas Mutables (ArrayList / MutableList): Creadas con arrayListOf(...) o mutableListOf(...). Métodos adicionales: add(elem), add(index, elem), remove(elem), removeAt(index), set(index, elem), isEmpty().

5. Estructuras de Control

Condicionales: if, if-else y when

En Kotlin, tanto if-else como when son expresiones que pueden retornar un valor y asignarse directamente a una variable. La estructura when sustituye y amplía con creces al clásico switch de Java:

val nota = 8
val calificacion = when (nota) {
    in 0..4 -> "Suspenso"
    5, 6 -> "Bien"
    7, 8 -> "Notable"
    9, 10 -> "Sobresaliente"
    else -> "Nota inválida"
}

Bucles: for, while y do-while

// for-each sobre colecciones
for (nombre in listaNombres) { Log.d("TAG", nombre) }

// Rangos numéricos cerrados (0..5 incluye el 5)
for (i in 0..5) { ... }

// Intervalo semiabierto con until (de 0 hasta size - 1)
for (i in 0 until lista.size) { ... }

// Con saltos personalizados mediante step
for (i in 0..10 step 2) { ... }

// Hacia atrás mediante downTo
for (i in 10 downTo 0) { ... }

// while y do-while convencionales
var cont = 0
while (cont < 5) { cont++ }
do { cont-- } while (cont > 0)

6. Lambdas y Funciones de Orden Superior

Una expresión lambda es una función anónima definida entre llaves { a, b -> a + b }. Si solo recibe un parámetro, se puede omitir su declaración explícita y referenciarlo con la palabra clave implícita it. Las funciones de orden superior son aquellas que reciben funciones o lambdas por parámetro:

  • filter { condición }: Devuelve los elementos que cumplen un predicado booleano.
  • find { condición }: Retorna el primer elemento coincidente, o null si ninguno cumple.
  • map { transformación }: Transforma cada elemento devolviendo una nueva colección transformada.
  • forEach { acción }: Itera ejecutando un bloque sobre cada ítem.
val precios = listOf(8.5, 15.0, 4.5, 20.0, 12.0, 7.0)
// Encadenamiento fluido: filtrar >= 10, aplicar 10% de descuento e imprimir
precios.filter { it >= 10.0 }
       .map { it * 0.9 }
       .forEach { Log.d("TAG", "Precio con descuento: $it") }

7. Control de Errores (Manejo de Excepciones)

try {
    val array = arrayListOf(1, 2, 3)
    val dato = array[10] // Provoca IndexOutOfBoundsException
} catch (e: IndexOutOfBoundsException) {
    Log.e("TAG", "Error capturado: ${e.message}")
} finally {
    Log.d("TAG", "Bloque finally: se ejecuta siempre para limpieza de recursos")
}
TEMA 4: Primer Contacto Con el Código y Ciclo de Vida de una Aplicación

1. Componentes de Arquitectura del Sistema Android

En el sistema operativo Android no existe una función main() convencional para arrancar el programa. Las aplicaciones se ejecutan en procesos independientes en un espacio aislado (sandbox). Los componentes fundamentales son:

  • Activity: Punto de entrada con ventana gráfica. En desarrollos con Jetpack Compose se implementa la arquitectura Single-Activity Architecture, en la cual una única actividad aloja la navegación entre múltiples funciones composables sin necesidad de destruir o recrear actividades.
  • Composable: Funciones declarativas marcadas con @Composable que representan elementos de la pantalla (Text, Button, Row, Column, etc.).
  • Service: Procesos en segundo plano sin UI que realizan operaciones continuas (descargas, reproducción multimedia, sincronización).
  • Content Provider: Proveedor para compartir datos de manera estructurada y segura entre aplicaciones bajo control de permisos (contactos, galería).
  • Broadcast Receiver: Receptor de avisos globales del sistema u otras apps (batería baja, cable de red, modo avión).
  • Widget: Vistas ligeras e interactivas empotradas en la pantalla de inicio del lanzador del dispositivo (reloj, calendario).
  • Intent: Objeto de mensajería utilizado para solicitar acciones a otros componentes o invocar aplicaciones externas (marcar un teléfono, abrir un mapa o navegador).

2. El Componente Activity y Pila de Navegación

La actividad principal de la app extiende de ComponentActivity. El punto de entrada se gestiona en el método onCreate(), asociando la interfaz mediante la función setContent { ... }. En una arquitectura de actividad única, las pantallas se apilan conceptualmente en una pila de navegación (back stack) según el principio LIFO (Last-In, First-Out): al navegar hacia adelante se realiza un push a la cima de la pila; al pulsar el botón "Atrás", se produce un pop que destruye la pantalla actual y revela la inmediata inferior.

3. Ciclo de Vida de una Activity (Lifecycle)

Una actividad pasa por diversos estados según su presencia en memoria RAM, su visibilidad y su capacidad de interactuar con el usuario:

Estado ¿En memoria? ¿Visible al usuario? ¿En primer plano? Transición / Métodos Callback
Inexistente No No No Llamada a onCreate() para crearse o eliminada tras onDestroy().
Detenida Sí No No Se alcanza tras onStop(). Vuelve a iniciarse mediante onRestart() → onStart().
Pausada Sí Sí No Alcanzada tras onStart() o cuando pierde el foco en onPause() (p. ej. diálogo superpuesto).
En Marcha Sí Sí Sí Alcanzada tras onResume(). La app interactúa plenamente con el usuario.

4. Acceso a Recursos (Clase R) e Internacionalización

Android genera automáticamente la clase R, que almacena identificadores enteros para acceder a los recursos del directorio res/:

  • Cadenas (res/values/strings.xml): Se obtienen en Compose con stringResource(id = R.string.nombre).
  • Imágenes (res/drawable/): Se obtienen con painterResource(id = R.drawable.nombre) para formatos PNG, JPG o XML vectorial.
  • Unidades de Medida:
    • dp (density-independent pixels): Para dimensiones, márgenes, paddings y tamaños de contenedores.
    • sp (scale-independent pixels): Exclusivo para texto; escala según las preferencias de accesibilidad del usuario en el sistema.
    • px (pixels): Píxeles físicos del panel; no recomendado para diseño adaptable.
  • Internacionalización (i18n): Se configura mediante el Translations Editor (botón derecho sobre strings.xml → Open Translations Editor), añadiendo locales como Spanish (es). Compose cargará dinámicamente la traducción según el idioma configurado en el terminal.
TEMA 5: Diseño de Interfaces de Usuario con Jetpack Compose

1. Paradigma Declarativo vs Imperativo

Frente al desarrollo imperativo clásico en XML (donde se declaraba una vista y se debía buscar con findViewById para mutarla paso a paso), Jetpack Compose adopta un modelo declarativo en Kotlin puro: se describe qué debe mostrar la pantalla en función del estado actual. Cuando los datos cambian, Compose ejecuta una recomposición inteligente, redibujando únicamente los componentes que leen esos datos.

Buenas Prácticas para Funciones @Composable

  1. Nombrado en PascalCase (ej. PantallaPrincipal, TarjetaProducto), nunca en camelCase.
  2. El nombre debe ser un sustantivo o sintagma nominal (ej. BotonAceptar), nunca un verbo de acción (evitar GetTexto).
  3. Deben ser públicas para favorecer la reutilización modular en distintos paquetes de la aplicación.

2. Material Design 3 y API MaterialTheme

Material Design 3 (Material You) enfatiza la accesibilidad, paletas dinámicas basadas en el fondo de pantalla (Android 12+) y consistencia visual en el ecosistema Android. Se estructura en el paquete ui.theme con tres archivos Kotlin:

  • Color.kt: Define constantes cromáticas en formato hexadecimal (ej. val DarkRed = Color(0xFF800000)).
  • Type.kt: Configura la tipografía con instancias de TextStyle (fuente, peso, tamaño, espaciado).
  • Theme.kt: Combina esquemas claros y oscuros (LightColorScheme y DarkColorScheme) con soporte para dynamicDarkColorScheme() y dynamicLightColorScheme().

Propiedades de MaterialTheme.colorScheme

  • primary / onPrimary: Color primario predominante y color del contenido sobre él.
  • secondary / onSecondary: Color complementario de acento.
  • tertiary / onTertiary: Color de contraste secundario.
  • background / onBackground: Color del fondo general de la pantalla y su texto.
  • surface / onSurface / surfaceVariant: Color para superficies elevadas (tarjetas, modales).
  • error / onError: Indicador de error (habitualmente tonos rojizos).

Propiedades de MaterialTheme.typography

  • Display: displayLarge, displayMedium, displaySmall (titulares de gran escala en pantallas destacadas).
  • Headline: headlineLarge, headlineMedium, headlineSmall (títulos intermedios de sección).
  • Title: titleLarge, titleMedium, titleSmall (encabezados de tarjetas y barras de herramientas).
  • Body: bodyLarge, bodyMedium, bodySmall (párrafos y lectura de texto continuo).
  • Label: labelLarge, labelMedium, labelSmall (etiquetas de botones y textos auxiliares).

3. Modificadores (Modifier)

Son objetos inmutables encadenables mediante el operador punto . que transforman el diseño, tamaño, bordes y comportamiento táctil. El orden de encadenamiento es estricto y se evalúa de arriba hacia abajo:

Modifier
    .fillMaxSize()                           // 100% de la pantalla
    .fillMaxWidth()                          // 100% de la anchura
    .fillMaxHeight()                         // 100% de la altura
    .size(100.dp)                            // Dimensiones cuadradas
    .width(200.dp).height(50.dp)             // Anchura y altura independientes
    .padding(horizontal = 16.dp, vertical = 8.dp) // Márgenes interiores
    .background(Color.Yellow)                // Fondo de color
    .border(width = 2.dp, color = Color.Black, shape = RoundedCornerShape(4.dp))
    .clip(CircleShape)                       // Recorte con forma
    .weight(1f)                              // Reparto proporcional en Row/Column
    .clickable { /* Acción táctil */ }

4. Contenedores de Diseño (Layouts)

  • Column: Organiza verticalmente. Parámetros: horizontalAlignment (Alignment.Start, CenterHorizontally, End) y verticalArrangement (Arrangement.Top, Center, Bottom, SpaceEvenly, SpaceBetween, SpaceAround, spacedBy(X.dp)).
  • Row: Organiza horizontalmente. Parámetros: verticalAlignment (Alignment.Top, CenterVertically, Bottom) y horizontalArrangement (Arrangement.Start, Center, End, SpaceEvenly, SpaceBetween, spacedBy(X.dp)).
  • Box: Apila en el eje Z (profundidad). Parámetros: contentAlignment (Alignment.Center, TopStart, BottomCenter, etc.). Los hijos admiten Modifier.align(...) individual.

2. Reutilización y Modularización de Composables

Para construir interfaces limpias y escalables se extraen componentes a funciones reutilizables con parámetros personalizables y valores por defecto. Estas funciones no necesitan residir en MainActivity.kt; se organizan en archivos Kotlin independientes (como Componentes.kt):

    mensaje: String,

    tamanoTexto: TextUnit = 20.sp
) {
    Text(

        color = colorTexto,
        fontSize = tamanoTexto
    )
}

3. Estados en Jetpack Compose (State Management)

Un estado es cualquier valor mutable que incide directamente sobre la representación visual de la pantalla. Al modificarse, Compose dispara una recomposición, volviendo a renderizar únicamente los Composables que leen la variable alterada.

  • remember { mutableStateOf() }: Conserva el valor en memoria durante sucesivas recomposiciones de la UI. Sin embargo, se reinicia a su valor por defecto si la actividad es destruida y recreada (por ejemplo, al rotar el dispositivo).
  • rememberSaveable { mutableStateOf() }: Almacena internamente el dato en un Bundle de Android, por lo que persiste frente a cambios de configuración como giros de pantalla.
  • Primitivas optimizadas: Para evitar sobrecostes de autoboxing se recomienda usar mutableIntStateOf(0), mutableLongStateOf(0L), mutableFloatStateOf(0f) y mutableDoubleStateOf(0.0).
  • Delegación con la palabra clave by: Al declarar var valor by rememberSaveable { mutableStateOf("") }, se delega el getter y setter al objeto MutableState, permitiendo leer y escribir directamente la variable sin usar .value.
TEMA 7: Componentes Avanzados, Listas Dinámicas y Scaffolding

1. Listas y Rendimiento (Lazy)

Las listas se emplean para mostrar múltiples elementos de forma ordenada (contactos, películas, productos). Jetpack Compose proporciona componentes Lazy que optimizan el rendimiento creando y renderizando en memoria únicamente los elementos visibles en la pantalla (bajo demanda). Esto minimiza el consumo de recursos al hacer scroll en conjuntos de datos masivos.

  • LazyColumn: Muestra los elementos en una lista vertical, permitiendo desplazamiento de arriba a abajo. Parámetros clave: modifier, contentPadding, horizontalAlignment y verticalArrangement (ej. Arrangement.spacedBy(10.dp)).
  • LazyRow: Muestra los elementos en una lista horizontal, permitiendo desplazamiento de izquierda a derecha. Parámetros análogos enfocados en el eje contrario: verticalAlignment y horizontalArrangement.

Elementos internos: item e items

Dentro del bloque de contenido de un Lazy layout, se estructura la lista usando funciones específicas:

  • items(lista) { elemento -> ... }: Itera sobre una colección de datos generando el bloque composable repetidamente para cada elemento de la lista.
  • item { ... }: Añade un único elemento estático en una posición concreta, ideal para añadir encabezados, títulos o espacios extra.
Sintaxis Básica de LazyColumn
LazyColumn(
    modifier = Modifier.fillMaxSize(),
    verticalArrangement = Arrangement.spacedBy(8.dp)
) {
    item { Text("Encabezado de la lista") } // Elemento estático único
    
    items(elementList) { element ->         // Generación dinámica
        Text(text = element)
    }
}

2. Dropdown Menu

El DropdownMenu es un menú desplegable de opciones oculto por defecto que se hace visible mediante la interacción con un control (como un botón o icono). Depende obligatoriamente de una variable de estado booleana para controlar su apertura/cierre.

  • DropdownMenu: Contenedor padre. Parámetros principales: expanded (estado booleano) y onDismissRequest (acción al hacer clic fuera, habitualmente cambiar el estado a false).
  • DropdownMenuItem: Cada opción seleccionable del menú. Parámetros: text, onClick, leadingIcon y trailingIcon.
Implementación de DropdownMenu
var estaDesplegado by remember { mutableStateOf(false) }

Button(onClick = { estaDesplegado = true }) {
    Text("Desplegar Menú")
}

DropdownMenu(
    expanded = estaDesplegado,
    onDismissRequest = { estaDesplegado = false }
) {
    DropdownMenuItem(
        text = { Text("Opción 1") },
        onClick = { estaDesplegado = false /* lógica extra */ }
    )
}

3. Estados con Listas (mutableStateListOf)

Cuando una aplicación requiere gestionar listas de las que se puedan agregar, editar o eliminar elementos en tiempo real y reflejar dichos cambios en la interfaz, se debe utilizar mutableStateListOf.

  • Debe declararse combinándolo exclusivamente con remember (nunca con rememberSaveable).
  • Notifica automáticamente las mutaciones al motor de Compose para redibujar LazyColumn o LazyRow.
  • Operaciones permitidas: add(elemento), add(posicion, elemento), remove(elemento), removeAt(posicion), set(posicion, elemento), clear().

4. Scaffold y Estructuras Base

Scaffold es un layout contenedor que implementa de forma automática y estandarizada la estructura visual canónica de Material Design para una pantalla. Administra el espacio para las barras de herramientas y menús sin que el desarrollador deba alinearlos manualmente.

Componentes y Parámetros del Scaffold

Componente Scaffold Descripción Técnica
topBar Recibe habitualmente un TopAppBar, proporcionando título, un navigationIcon (botón de atrás o menú) y botones de acción (actions) a la derecha.
bottomBar Recibe un BottomAppBar o NavigationBar. Aloja acciones frecuentes en la base de la pantalla.
floatingActionButton Botón circular destacado (FAB) que representa la acción principal (ej. añadir un elemento nuevo). Flota sobre el contenido en la esquina inferior derecha.
content Cuerpo principal de la pantalla. Recibe un parámetro paddingValues que debe ser aplicado obligatoriamente al contenedor interno (como un Box o Column) para evitar que el contenido se superponga detrás de las barras.

5. Patrón de Diseño: State Hoisting

State Hoisting (Elevación de Estado) es un patrón de arquitectura en Compose que consiste en mover (elevar) el estado interno de un componente hacia su Composable padre. Esto favorece la reutilización y el principio de responsabilidad única.

  • El componente hijo (*Stateless*) no almacena el estado internamente.
  • El hijo recibe el valor actual del estado por parámetro.
  • El hijo recibe una función lambda (callback) por parámetro, que invoca cuando necesita notificar una mutación del dato, dejando que el padre actualice la variable.
Implementación de State Hoisting
// 1. Componente Padre (Mantiene el Estado)
@Composable
fun PantallaPrincipal() {
    var nombre by remember { mutableStateOf("") }
    // Pasa el estado y el callback
    TextFieldNombre(nombre = nombre, onTextChange = { nombre = it })
}

// 2. Componente Hijo (Stateless / Reutilizable)
@Composable
fun TextFieldNombre(nombre: String, onTextChange: (String) -> Unit) {
    OutlinedTextField(
        value = nombre,
        onValueChange = onTextChange, // Propaga el cambio al padre
        label = { Text("Escribe tu nombre") }
    )
}
